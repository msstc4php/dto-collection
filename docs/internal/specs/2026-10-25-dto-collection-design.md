# dto-collection: дизайн

Дата: 2026-10-25 (UTC). Статус: черновик на согласование.

Пометка **[решение Claude]** означает выбор, сделанный в ходе обсуждения без явного
подтверждения владельца; остальное сказано владельцем.

## 1. Зачем

В PHP нет типизированных массивов. Нужна библиотека типизированных списков, где тип
элемента виден **в нативных type hint сигнатур**: `push(User $element)`,
`first(): ?User`. Не в PHPDoc и не только через рантайм-ассерты.

Это первый из трёх независимых проектов:

1. **`msstc4php/dto-collection`**, этот документ. Runtime-библиотека: трейты,
   интерфейсы, обобщённая коллекция, ODM-вариант.
2. **`dto-collection-generator`**, следующий шаг. Генерирует конкретные нативно
   типизированные классы поверх этой библиотеки по спекам: повторяемый атрибут на DTO
   или конфиг-файл (для скаляров и чужих классов). На один DTO можно описать несколько
   коллекций, каждая со своим FQCN и вариантом.
3. **dto-generator: «объект-коллекция вместо массива».** Универсальная возможность
   подставлять вместо `array` + `@var list<T>` любой класс коллекции, не только наш.
   dto-generator не зависит от проектов 1 и 2.

Библиотека проектируется так, чтобы генератору (2) было что генерировать, а
dto-generator (3) мог подключить её как «один из классов коллекций».

## 2. Цели

- Список элементов одного типа с нативной типизацией в сгенерированных (или
  рукописных) классах.
- Типы элементов: `int`, `string`, `float`, `bool`, любой класс или интерфейс,
  nullable (`?T`), union (`A|B|null`), intersection (`A&B`).
- Три варианта: **immutable**, **mutable**, **ODM** (Doctrine MongoDB ODM,
  `collectionClass`).
- Готовая обобщённая коллекция для работы без генератора.
- Лучшие методы lodash-php и voku/Arrayy без их багов и алиасов, плюс то, чего нет в
  обеих (раздел 7).
- Сопровождаемость и отсутствие багов. Это главное требование владельца, см. раздел 10.

## 3. Не цели

- **Словари и ключи, отличные от `0..n-1`.** Только списки с последовательными
  целыми ключами.
- **Doctrine ORM.** ORM жёстко подставляет `PersistentCollection`, штатно заменить её
  нельзя, а хаки ломают change tracking. Из Doctrine поддерживается только ODM.
- Наследование от `ArrayCollection`. Типизированный `add(User $e)` несовместим с
  `Collection::add(mixed)`, так как PHP запрещает сужать тип параметра.
- Выборка по строковым путям и именам свойств (`pluck('a.b')`, `where('field', …)`,
  iteratee-шорткаты lodash). Только замыкания.
- Ленивые последовательности в первой версии [решение Claude].
- DNF-типы (`(A&B)|null`), так как это PHP 8.2+. При повышении минимальной версии их
  можно добавить.

## 4. Анти-цели

- Библиотека, которую трудно сопровождать.
- Библиотека с багами.
- Сокращённые имена. Пишем полностью: `ListOf::integers()`, а не `ints()`;
  `averageBy`, а не `avgBy`. Общепринятые `min`/`max` допустимы [решение Claude].

## 5. Ограничения

- **Две мажорные линии по версиям PHP** (решение владельца):
  - **1.x — PHP 8.1–8.4.** Порог 8.1 — это порог `doctrine/collections` 2.x и ODM; в
    8.1 есть `mixed`, union, `readonly` свойства, enum, `never`. Код 1.x не использует
    синтаксис и функции PHP 8.2+.
  - **2.x — PHP 8.5+.** Внутри использует возможности 8.5: `clone with` для
    with-методов, `array_first`/`array_last` и т.п.
  - Публичный API у линий одинаковый: одни и те же классы, методы и поведение, разница
    только во внутренней реализации и в нижней границе PHP [решение Claude]. Код,
    написанный против 1.x, работает на 2.x без изменений.
  - Минимум до 8.5 не повышаем: пользователи 8.1–8.4 остаются на 1.x.
  - **Ведение — две ветки, `1.x` и `2.x`, руками** (решение владельца; автоматический
    даунгрейд Rector'ом отклонён). Чтобы линии не расходились [решение Claude]:
    - сначала делается и стабилизируется 1.x, ветка `2.x` создаётся от неё после 1.0;
    - исправления и новые методы идут сначала в `1.x`, потом `1.x` **мержится** вверх
      в `2.x` (merge-up, не cherry-pick);
    - в `2.x` меняется только внутренняя реализация под 8.5. Контрактный набор тестов
      общий и в `2.x` не правится, кроме случаев, когда меняется только реализация;
    - BC-check в `2.x` сравнивает публичный API с `1.x`.
- **Генератор (проект 2) получает ключ целевой версии PHP** (решение владельца) и
  генерирует код с учётом её возможностей: на 8.5+ — с фичами 8.5 и зависимостью на
  `dto-collection` 2.x, ниже — на 1.x. В этой библиотеке это фиксируется только как
  требование: API не должен мешать такой генерации.
- dto-generator генерирует код для PHP 7.4–8.5. Наши коллекции он сможет подставлять
  только для таргетов ≥ 8.1. Это забота проекта 3, здесь только фиксируем.
- `doctrine/collections` и `doctrine/mongodb-odm` — только `suggest` и `require-dev`.
  Ядро от них не зависит.
- Пакет `msstc4php/dto-collection`, неймспейс `MSSTC4PHP\DtoCollection`, каталог
  `~/PhpstormProjects/msstc4php/dto-collection` [решение Claude, по аналогии с
  dto-generator].

## 6. Модель

### 6.1 Инвариант списка

Ключи всегда `0..n-1` подряд. Каждая операция, которая удаляет или переставляет
элементы (`filter`, `remove`, `unique`, `sliced`, `sort`…), переиндексирует. `set(int
$index, T $e)` разрешён для существующего индекса и для `index === count()`
(дописать в конец), иначе исключение.

### 6.2 Варианты

| Вариант | `final` | Изменение | Возврат мутаторов | Прочее |
|---|---|---|---|---|
| Immutable | да | только через `with*`/`without*` → новый экземпляр | — | |
| Mutable | да | мутаторы меняют объект на месте | `void` | |
| ODM | **нет** | как Mutable | `void` | реализует `Doctrine\Common\Collections\Collection<int, T>`; конструктор без аргументов |

Во всех вариантах методы-запросы (`filter`, `transform`, `sorted`, `sliced`…)
возвращают **новый экземпляр** [решение Claude, по итогам ревью].

Мутаторы возвращают `void` [решение Claude]. Причины: стиль интерфейса Doctrine;
fluent `return $this` в ODM-обёртке возвращает внутреннюю коллекцию, а не обёртку;
случайное использование мутатора как запроса становится ошибкой статанализа.

Преобразования между вариантами: `toMutable()`, `toImmutable()` [решение Claude].
В трейтах и интерфейсах они возвращают обобщённые `MutableListOf<T>` / `ListOf<T>`.
Если для DTO описаны спеки обоих вариантов, генератор может сузить возврат (covariant)
до сгенерированного парного класса.

### 6.3 ODM-вариант: жёсткие требования (проверено по исходникам doctrine/mongodb-odm)

- Класс указывается в `#[ODM\EmbedMany(collectionClass: …)]` /
  `#[ODM\ReferenceMany(collectionClass: …)]` и обязан реализовывать `Collection`.
- ODM создаёт экземпляр через `new $class()`, поэтому нужен конструктор без
  обязательных аргументов.
- ODM генерирует наследника, поэтому класс не `final`. `final` public-методы и
  static-методы не проксируются.
- У всех параметров должны быть типы. Дефолты выводятся через `var_export`, поэтому в
  дефолтах не может быть объектов и enum.
- Методы интерфейса объявлены с `mixed`. Их реализация проверяет тип в рантайме и
  бросает исключение. Рядом с ними идут нативно типизированные методы под своими именами
  (см. 7.6).
- Ключи интерфейса — `int`, инвариант 6.1 держим сами: `remove()` в
  `ArrayCollection` дырки оставляет, у нас переиндексирует.
- Для `EmbedMany`/`ReferenceMany` с нашей коллекцией в документации рекомендуем
  стратегию `setArray`/`atomicSetArray`, чтобы в Mongo хранился массив, а не объект с
  ключами [решение Claude; проверить на интеграционном тесте].
- **Риск, проверить на реализации:** хранит ли ODM `null`-элементы в
  `EmbedMany`/`ReferenceMany`. Если нет, nullable-элементы для ODM-варианта
  объявляются неподдерживаемыми (генератор их запретит), и это документируется.

### 6.4 Тип элемента и проверка

- В сгенерированном или рукописном конкретном классе тип проверяет PHP через нативные
  type hint публичных методов. Трейты внутри работают с нетипизированным хранилищем
  (`list<mixed>` на уровне языка, `list<T>` в PHPDoc).
- В обобщённой коллекции (6.6) и в `mixed`-методах ODM-варианта тип проверяется в
  рантайме при каждом добавлении. Ошибка — собственное исключение библиотеки с индексом,
  ожидаемым и фактическим типом [решение Claude].
- Для рантайм-проверки нужен объект-описание типа элемента (`ElementType`): одиночный
  тип, nullable, union, intersection; разбор из строки (`'Cat|Dog|null'`) и сборка
  программно. Генератор (проект 2) использует ту же модель [решение Claude].
- Методы, меняющие тип элемента и возвращающие обобщённую коллекцию (`mapTo`,
  `flatMapTo`), **требуют явный целевой тип**: `mapTo(User::class, fn …)` или `ElementType`.
  Тип `mixed`/«любой» в `ElementType` не вводим: так ошибки ловятся сразу, что
  соответствует анти-цели «без багов». Без проверки типа остаётся `mapToArray`
  [решение Claude].

### 6.5 Равенство элементов

Нужно для `contains`, `positionOf`, `removeElement`, `unique`, `diff`, `intersect` и т.п.

- Скаляры сравниваются через `===`, в том числе `float`. Это осознанно и
  документируется.
- У объекта есть метод `equals()` → `$a->equals($b)`.
- У объекта нет `equals()` → по идентичности (`spl_object_id`, по сути `===`).
- `null === null`.
- В union стратегия выбирается для каждой ветки типа. Объекты разных классов-веток
  никогда не равны [решение Claude].

Как определяется стратегия [решение Claude]:
- генератор видит класс на этапе генерации и выбирает стратегию статически;
- рукописная коллекция объявляет стратегию явно (метод или константа класса);
- в библиотеке есть интерфейс `Equatable` для явности;
- угадывать через `method_exists` в рантайме **не** будем: чужой `equals()` с другой
  сигнатурой молча даст неверный результат. Исключение — обобщённая коллекция, ей
  стратегию передают при создании или она выводит её из `ElementType`: `Equatable` →
  `equals()`, иначе идентичность. Конкретный механизм остаётся строителю.

Цена: операции над множествами с `equals()` работают за O(n²), с идентичностью и для
скаляров — за O(n) через хеш-таблицу. Это документируется.

### 6.6 Обобщённая коллекция (без генератора)

- `ListOf` (immutable) и `MutableListOf` (mutable) [имена — решение Claude].
- Фабрики: `ListOf::of(User::class, $elements)`, `ListOf::integers([...])`,
  `ListOf::strings([...])`, `ListOf::floats([...])`, `ListOf::booleans([...])`,
  `ListOf::ofType('Cat|Dog|null', $elements)` / с объектом `ElementType`.
- Тип проверяется в рантайме. PHPStan видит `ListOf<User>` через `@template`.
- ODM-варианта у обобщённой коллекции нет: `collectionClass` требует конкретный класс и
  конструктор без аргументов [решение Claude].
- Реализация общая с конкретными классами, через те же трейты.

### 6.7 Трейты и интерфейсы

- Трейты сгруппированы по смыслу: создание, доступ, поиск и предикаты, трансформации,
  сортировка, агрегаты, множества, структура (split/group/chunk), мутаторы,
  with/without, экспорт. Плюс по одному агрегирующему трейту «всё включено» на
  вариант [решение Claude]. Точное разбиение остаётся строителю.
- Трейты не объявляют публичных методов с типом элемента. Публичный типизированный
  фасад — забота конкретного класса, который генерирует проект 2 или пишут руками. Трейты
  дают protected-реализацию, которой фасад делегирует. Чтобы обобщённая коллекция и
  ODM-вариант не дублировали фасад, допустимы готовые public-обёртки с `mixed` в
  отдельных трейтах [решение Claude, детали — строителю].
- Интерфейсы: общий для чтения (без типа элемента в сигнатурах, generics в PHPDoc),
  отдельно mutable и immutable. Сгенерированный класс реализует их, чтобы на коллекции
  можно было писать обобщённый код [решение Claude].
- Интероп во всех вариантах: `IteratorAggregate`, `Countable`, `JsonSerializable`,
  `ArrayAccess` **только на чтение**: `offsetSet`/`offsetUnset` бросают исключение,
  кроме ODM, где этого требует интерфейс Doctrine [решение Claude].
- Создание: `fromArray(list<T>)`, `of(T ...$elements)`, `empty()`; экспорт:
  `toArray(): list<T>`. Это контракт, который потом использует dto-generator
  (проект 3) [решение Claude].

## 7. Набор методов

Основа — ревью lodash-php и voku/Arrayy от 2026-10-25 UTC (исходники последних
версий). Полный отчёт с таблицами лежал в scratchpad сессии, его содержание сведено
сюда.

### 7.1 Что не переносим

- Баги lodash-php: `head`/`first` возвращают `null` при falsy первом элементе;
  `uniq`/`difference`/`intersection` сравнивают через строки и ломаются на объектах;
  `sortBy` с несколькими ключами делает главным последний ключ.
- Непоследовательная мутабельность Arrayy (`reverse`, `unique` мутируют, `filter` нет),
  пары `X`/`XImmutable`, алиасы (`count`/`size`/`length`, `toArray`/`getArray`/`getAll`),
  `find` → `false`, `each` как map, `reduce`, оборачивающий результат.
- Dot-notation, селекторы по имени свойства, API по ссылке, зеркала PHP-sort-флагов,
  проверки формы (`isAssoc` и т.п.), JSON/строковые фабрики, `toPermutation`,
  `randomWeighted`.

### 7.2 Правила именования и сигнатур [решение Claude]

- Замыкания получают `(T $element, int $index)`. Только Doctrine-методы ODM-варианта
  (`exists`, `forAll`, `partition`, `findFirst`) вызывают замыкание с `(key, element)`,
  как требует интерфейс.
- «Не найдено» — `null`. Строгие версии `*OrFail()` бросают собственное исключение.
  Для nullable-коллекций `first()` не отличает «пусто» от «первый элемент null», для
  этого и есть `firstOrFail()` и `isEmpty()`.
- **Наши имена не пересекаются с именами `Doctrine\Collection`, если семантика
  отличается** (решение владельца, вариант A). Метод с одним именем ведёт себя одинаково во
  всех трёх вариантах. Doctrine-методы с доктриновской семантикой есть только в
  ODM-варианте, ради интерфейса (7.7). Конкретно:
  - смена типа: `mapTo(ElementType|string $type, Closure(T, int): U): ListOf<U>` и
    `flatMapTo(...)`; `map` в нашем API нет;
  - тот же тип: `transform(Closure(T, int): T): static`;
  - позиция: `positionOf(T): ?int`; `indexOf` в нашем API нет;
  - разбиение: `split(Closure(T, int): bool): array{static, static}`; `partition` в
    нашем API нет;
  - предикаты: `any` / `all` / `none`; `exists` / `forAll` в нашем API нет;
  - поиск: `find`; `findFirst` в нашем API нет;
  - срез: `sliced(int $offset, ?int $length = null): static`, в одном ряду с `sorted`,
    `reversed`, `shuffled`; `slice` в нашем API нет;
  - совпадающие по смыслу имена допустимы во всех вариантах: `filter`, `contains`, `get`,
    `remove`, `removeElement`, `clear`, `isEmpty`, `count`, `toArray`, `first`, `last`,
    `reduce`. В ODM их сигнатуры подчиняются интерфейсу (`mixed` + рантайм-проверка,
    `reduce($initial = null)`), а поведение то же. `filter` в ODM тоже переиндексирует.
- Полные слова в именах (раздел 4).

- **`#[\NoDiscard]`** (решение владельца) стоит на всех методах, результат которых
  нельзя выбрасывать: все запросы, возвращающие коллекцию или значение, все
  `with*`/`without*`, `toMutable`/`toImmutable`, `mapTo` и т.п. На 1.x атрибут
  объявлен, но движок 8.1–8.4 его игнорирует; на 8.5+ PHP предупреждает о
  выброшенном результате, например `$list->with($user);` без присваивания. Генератор
  ставит атрибут и на сгенерированные публичные методы.

### 7.3 Создание (все варианты)

`of(T ...)`, `fromArray(list<T>)`, `fromIterable(iterable<T>)`, `empty()`; конструктор
(в ODM — без обязательных аргументов).

### 7.4 Чтение и запросы (все варианты)

| Группа | Методы |
|---|---|
| размер | `count`, `isEmpty`, `isNotEmpty` |
| доступ | `first`, `last`, `firstOrFail`, `lastOrFail`, `get(int)`, `getOrFail(int)`, `at(int)` (отрицательный — с конца), `single` (ровно один, иначе исключение), `singleOrNull`, `random` |
| поиск | `contains`, `containsAll`, `containsAny`, `positionOf`, `find`, `findLast`, `findPosition` |
| предикаты | `any`, `all` (true на пустой), `none`, `countWhere`, `countBy` |
| агрегаты | `reduce`, `sumBy`, `averageBy`, `minBy`, `maxBy`; для числовых скаляров `sum`, `average`, `min`, `max`; для строк `join` |
| тот же тип | `filter`, `reject`, `transform`, `sliced`, `take`, `takeLast`, `drop`, `dropLast`, `takeWhile`, `dropWhile`, `unique`, `uniqueBy`, `sorted`, `sortedBy` (с `thenBy`-цепочкой или списком селекторов — строителю), `reversed`, `diff`, `diffBy`, `intersect`, `intersectBy`, `union`, `merge`, `shuffled` |
| структура | `split` → `array{static, static}`, `groupBy` → `array<array-key, static>`, `chunk(positive-int)` → `list<static>`, `windowed`, `chunkWhile` |
| смена типа | `mapTo` → `ListOf<U>`, `flatMapTo` → `ListOf<U>`, `mapToArray` → `list<U>`, `mapInto(class-string<C>, Closure)` → `C` (заданная типизированная коллекция), `keyBy` → `array<array-key, T>` |
| прочее | `each` (побочный эффект, `false` прерывает), `pipe(Closure(static): R): R` |
| экспорт | `toArray`, `jsonSerialize`, `equals(self)` (поэлементно по 6.5) |

### 7.5 Только mutable и ODM

`push(T ...)`, `unshift(T ...)`, `set(int, T)`, `insertAt(int, T)`, `remove(int): ?T`,
`removeElement(T): bool`, `removeIf(Closure): int`, `pop(): ?T`, `shift(): ?T`,
`clear()`, `sort(Closure)`, `sortBy(...)`, `reverse()`, `swap(int, int)`,
`move(int $from, int $to)`.

### 7.6 Только immutable

`with(T ...)` (append), `withPrepended(T ...)`, `withSet(int, T)`,
`withInsertedAt(int, T)`, `without(int ...)`, `withoutElement(T ...)`,
`withoutIf(Closure)`, `withReplaced(T $old, T $new)`.

### 7.7 ODM: методы интерфейса Doctrine

`add`, `set`, `remove`, `removeElement`, `clear`, `containsKey`, `contains`, `get`,
`getKeys`, `getValues`, `toArray`, `first`, `last`, `key`, `current`, `next`, `slice`,
`exists`, `forAll`, `filter`, `map`, `partition`, `indexOf`, `findFirst`, `reduce`,
`ArrayAccess`, `isEmpty`, `count`, `getIterator`. Где сигнатура `mixed`, там
рантайм-проверка типа. Нужен ли `Selectable` (`matching(Criteria)`), решает строитель:
посмотреть, что ODM с ним делает.

`first()`/`last()` в Doctrine на пустой коллекции возвращают `false`. У нас `?T` (по
правилу 7.2; сужение возврата с `mixed` допустимо). Это расхождение с `ArrayCollection`
документируется [решение Claude].

### 7.8 Функциональный API для pipe-оператора (решение владельца)

Помимо методов есть набор функций в стиле lodash в неймспейсе
`MSSTC4PHP\DtoCollection\Pipe` [имя неймспейса — решение Claude]. Каждая функция
принимает параметры операции и возвращает замыкание от одной коллекции:

```php
use function MSSTC4PHP\DtoCollection\Pipe\{filter, sortedBy, take};

$top = $users
    |> filter(fn(User $u) => $u->isActive())
    |> sortedBy(fn(User $u) => $u->score(), descending: true)
    |> take(10);
```

- На PHP 8.5+ функции читаются через `|>`. На 8.1–8.4 они работают через метод
  `pipe(...)` коллекции или прямым вызовом. Функции есть в обеих линиях.
- Функции покрывают методы-запросы из 7.4 и with/without из 7.6. Мутаторы из 7.5 не
  покрывают: в конвейере результат передаётся дальше, а мутатор возвращает `void`
  [решение Claude].
- Функция — тонкий адаптер над методом, своей логики в ней нет. Поведение и тесты общие с
  методами [решение Claude].
- Тип элемента функции не знают (`@template` в PHPDoc). Нативная типизация остаётся
  за методами конкретного класса.
- `pipe(Closure(static): R ...$steps): R` у коллекции принимает несколько шагов
  [решение Claude].

## 8. Взаимодействие с проектами 2 и 3

- **Генератор (2)** генерирует конкретные классы: нативно типизированный публичный
  фасад, который делегирует трейтам; плюс выбор стратегии равенства. Библиотека должна
  дать ему стабильные трейты/интерфейсы и модель `ElementType`. Спеки и атрибут
  `#[TypedCollection]` относятся к проекту 2, но **атрибут живёт в этой библиотеке**,
  чтобы рукописные DTO зависели только от runtime-пакета [решение Claude]. Поля
  атрибута: FQCN коллекции, вариант (`immutable`/`mutable`/`odm`), `nullable: bool =
  false` и необязательный `elementType: ?string`. Если он не задан, тип элемента —
  класс, на котором стоит атрибут; если задан, это интерфейс, родитель или union, куда
  входит этот класс. Стратегию равенства генератор выводит сам. Новые поля потом
  добавляются только как необязательные, это не ломает BC [решение Claude].
- ODM-вариант допустим только для типов элементов-документов (embedded или
  referenced); генератор проверяет это [решение Claude].
- **dto-generator (3)** опирается на `fromArray(list<T>)` / `toArray(): list<T>`.

## 9. Что остаётся строителю

- Точное разбиение трейтов и интерфейсов, имена внутренних классов и исключений.
- Механизм объявления стратегии равенства в рукописной коллекции.
- Форма `sortedBy`/`thenBy`.
- `Selectable` в ODM-варианте.
- Разбор строки типа в `ElementType` (грамматика: имена классов, скаляры, `?`, `|`,
  `&`, `null`).
